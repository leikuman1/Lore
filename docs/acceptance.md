# 功能验收标准

全部业务项当前均未完成。实际实现并通过对应验证后才能勾选。依赖安装、文档描述或内存 mock 不能替代真实持久化和并发验证。

## 持久化任务与故障回收

- [ ] 提交后重启 API / Worker，仍可查询 Run、状态与执行记录。
- [ ] 重复投递、多个 Worker 并发领取时，只有一个持有当前有效租约；使用真实 PostgreSQL 验证条件更新与事务。
- [ ] 持续续租不触发接管；停止续租并超过有效期后可被补偿扫描重新投递，接管者取得更大 fence。
- [ ] 旧执行者在接管后提交终态，因旧 fence 被拒绝；当前执行者可正常完成。
- [ ] 提交后队列唤醒失败可通过补偿发现；正常重试的退避安排不会被扫描反复清空。

边界：租约过期不证明旧进程已停；fence 只约束检查它的写入方。外部动作须依靠幂等键或结果核对，不能宣称 exactly-once 或每个 token 均可恢复。

## 人工审批暂停与按原请求续跑

- [ ] 审批前保存工具身份、规范化原参数、pending call 和版本化 checkpoint；等待时释放执行租约，重启后审批仍可查询。
- [ ] 批准后入队，实际执行保存的原请求；恢复时篡改参数无效，修改动作需重新审批。
- [ ] 同一决策重复提交不重复推进；已成功保存的工具效果返回原结果，不再次发起外部调用。
- [ ] 在“外部动作可能成功但结果未落库”处故障注入，恢复后标记 uncertain 并等待核对，不盲目重放。
- [ ] 拒绝、过期或不属于当前主体的审批无法放行动作；可以查询决策与动作的关联记录。

边界：SDK 的工具审批接口不能替代应用的持久化协议；uncertain 是结果未知，不是成功或失败。审批等待节省执行上下文与租约，不声称异步等待一直占 CPU。

## 版本化记忆与上下文预算

- [ ] 两个写入者基于同一版本更新，仅一个提交成功，另一个收到冲突；修订可追踪。
- [ ] 摘要保存明确历史覆盖范围，构造覆盖缺口时不能静默当作完整历史。
- [ ] 扣除提示词、工具 schema 和输出预留预算；增大历史与工具结果时能观察到选择和缩短行为。
- [ ] 工具调用与结果整组保留 / 删除；必要内容仍超限时显式返回错误。
- [ ] 用包含早期事实、事实更新和任务依赖的用例独立评估摘要质量，不把结构测试视为事实正确证据。

边界：初版不包含向量检索；上下文预算使用估算值，不能替代精确 tokenizer。token 用量、成本和成功率需通过实际测量评估。

## 按需工具目录与调用时授权

- [ ] 小目录直出；超过明确且可配置的阈值后，初始输入不含全量工具 schema，只保留发现入口。
- [ ] search → load → execute 解析为真实服务和工具，无效目标 / 不符合真实 schema 的参数在外部调用前被拒绝。
- [ ] 用户、空间、Agent 分配和 allowlist 同时限制发现与执行；通用执行入口不能绕过。
- [ ] 发现或审批后撤销权限，实际调用时再次检查并拒绝；记录真实目标和授权决策。
- [ ] 使用一个外部 MCP fixture 服务展示完整链路，记录初始 schema 规模、发现步骤和失败原因，不仅测试函数返回。

边界：Lore 在这里是 MCP 客户端；stdio 不代表沙箱；调用前检查不消除所有撤权竞态。按需加载可减少初始定义，不能直接推导端到端更快。

## 验证记录

记录实现路径、实际执行的命令、通过与失败结果，以及可重复运行的验证场景。默认离线测试、真实数据库事务测试、真实模型任务评估分别记录；缺少凭据或未运行应写明，不作为通过。
